## Golden Rules

| # | Rule |
|---|------|
| 1 | `:core` is **pure Kotlin/JVM**. Never add `android.*` imports there. New pure logic → `:core` with unit tests. |
| 2 | UI talks to AI **only through `AiEngine`** — never providers/HTTP directly |
| 3 | Never hand-edit `core/.../prompt/DefaultPromptsData.kt` — it's generated by `tools/generate_default_prompts.py` |
| 4 | No emoji icons in UI — use Material icons (mapped by the prompt generator) |
| 5 | Never put real API keys in code, tests, logs, or exports |
| 6 | Small changes; run tests after each. Don't rewrite files that already work. |
| 7 | If docs contradict the compiler, trust the compiler and update the docs |

## Architecture Boundaries

| Boundary | Rule |
|----------|------|
| `:core` → `:app` | `:core` depends on nothing Android. All persistence uses `java.io.File`. |
| Features → AI | Features call `AiEngine` only. `AiEngine` → `ProfileResolver` → `ProviderRegistry` → `AiProvider.generate` |
| Provider subclasses | Only format request JSON and parse response JSON. Retry/rotation lives in `AiProvider.generate`. |
| Prompt editing | User edits mark actions `isDefault = false`. `PromptMerge` does 3-way merge on app updates. |

## Heuristics

| When | Do |
|------|----|
| Adding new AI provider | Subclass `AiProvider`, implement `buildRequestBody`/`parseResponseBody` only. Register in `ProviderRegistry`. |
| Adding new prompt action | Add to `tools/generate_default_prompts.py` mapping → regenerate → verify zero diff |
| Adding UI-only feature | Put it in `app/src/.../feature/`. State logic → `:core` if testable without Android. |
| Changing design tokens | Edit `designsystem/Color.kt`, `Type.kt`, `Shape.kt`. Run `contrast_audit.py`. |
| Touching storage/keys | Keep in `:core` (except `KeystoreSecretCipher` which needs Android Keystore) |

## CI

Tag push (`v*`) or manual dispatch → JDK 17 → `:core:test` → `:app:assembleRelease` → GitHub Release with APK. Signing via `KEYSTORE_BASE64` secret; debug keystore fallback.

## Boundaries

### Always Do
- Run `./gradlew :core:test` before committing
- Build APK if UI changed
- Show test output as evidence before claiming done
- Use conventional commit format: `type(scope): subject`

### Ask First
- Adding new dependencies
- Changing `compileSdk`, `minSdk`, or `targetSdk`
- Modifying the release signing config or CI workflow
- Changing public API signatures in `:core`

### Never Do
- Add `android.*` imports to `:core`
- Hand-edit `DefaultPromptsData.kt`
- Commit API keys, keystores, or `keystore.properties`
- Put emoji icons in the UI
- Render invented mock text in previews
- Use cards inside cards in the design system
- Use gradients, glow, or blur effects

## Design System

ONE cobalt accent (`#2447E0` light / `#8EA3FF` dark`). Diff: yellow inserts, struck red deletes. 12 dp control corners, 28 dp sheet tops, 48 dp touch targets. Type 24/20/16/14 Roboto (monospace for pixel sizes/model ids). Material icons only. No gradients/glow/blur, no cards inside cards, no emoji.

## Terminology

| Term | Means |
|------|-------|
| Action | A prompt action (Fix Grammar, Humanize, etc.) shown on the action bar |
| Modifier | Toggleable instruction (Shorter, Formal, Language) appended to requests |
| Profile | Connection profile = provider + endpoint + model + settings |
| Key pool | Multiple API keys per provider with automatic rotation on 429/401/403 |
| Snip | Screen capture → region crop → AI analysis flow |
| Tool | `ToolId.TEXT_EDIT` or `ToolId.SNIP` — determines which UI flow and prompt context |
