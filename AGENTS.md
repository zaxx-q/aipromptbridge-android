# AGENTS.md — instructions for the coding agent working in Android Studio

You are continuing **AIPromptBridge for Android**. Read `README.md` first (plan, architecture, decisions), then this file.
The project was authored **without a compiler**, so your first job is to make it build and pass its tests.

## Golden rules
1. `:core` is pure Kotlin/JVM. **Never add `android.*` imports there.** New pure logic goes in `:core` with unit tests.
2. UI talks to the AI only through `AiEngine` (never providers/HTTP directly).
3. Never hand-edit `core/.../prompt/DefaultPromptsData.kt` (generated by `tools/generate_default_prompts.py`).
4. Follow `design/stitch/editorial_precision/DESIGN.md` + `docs/DESIGN_NOTES.md`. Never render invented mock text. No emoji icons.
5. Never put real API keys in code, tests, logs, or anything exported.
6. Make small changes; after each one run `./gradlew :core:test` (and a build when UI changed). Don't rewrite files that already work.
7. If something in the docs contradicts what the compiler/IDE tells you, trust the compiler and update the docs.

## First session — do these in order, report after each
1. **Gradle sync.** If the AGP version is rejected by this IDE, adjust `agp` in `gradle/libs.versions.toml` (AGP Upgrade Assistant is fine).
   Run the `wrapper` Gradle task once so `./gradlew` exists. Gradle must be >= what the chosen AGP requires.
2. **`./gradlew :core:test`.** Fix compile errors and failing tests. For a failing test decide whether the **test or the code** is wrong
   (tests encode behaviour ported from the original Python app — see `docs/ORIGINAL_NOTES.md` and `reference/original-python/`); don't just weaken assertions.
3. **`./gradlew :app:assembleDebug`.** Likely trouble spots, most likely first:
   - `designsystem/AipbIcons.kt` — icon names / `material-icons-extended` availability (isolated to that file).
   - `designsystem/Components.kt` — Material3 parameter names (`Surface(onClick=…)`, `ModalBottomSheet`, `FilledIconButton`).
   - `feature/snip/*` — `startActivityAndCollapse`, `requestAddTileService`, MediaProjection APIs.
   - `core/.../provider/*Provider.kt` — kotlinx.serialization builder imports (`put`, `add`).
   - Versions in `gradle/libs.versions.toml` (they were taken from docs but never resolved offline).
4. **Open the `@Preview`s** in `designsystem/Previews.kt` (light + dark) and compare with `design/stitch/*/screen.png`.
   Fix visible deviations (spacing, colours, shapes) in the design system, not per-screen.
5. **Run on an emulator** (API 30+): setup screen → save a key → select text in another app → AIPromptBridge → *Fix Grammar* (README "Setup", steps 5-6).
   Write down anything that fails; fix it.
6. Commit (or at least tell the user what changed). Then continue with README **Phase 4+** in order.

## Good early improvements (high value, low risk)
- Extract stateless `TextEditSheetContent(state, …)` / `SnipActionSheetContent(…)` composables so every UI state
  (idle / loading / result / read-only result / error) can have a `@Preview` — then verify them against the Stitch screenshots.
- Add `@Preview`s for the Settings/Prompt-editor screens as they are built.
- Add a small `UrlConnectionTransport` test using `com.sun.net.httpserver.HttpServer` on the JVM if you move it into `:core` (optional).

## Definition of done for a phase
Builds clean · `:core:test` green · relevant UI matches the Stitch screen in light **and** dark · works on an emulator ·
no new `TODO` without a tag like `TODO(chat)` · README status table updated.
